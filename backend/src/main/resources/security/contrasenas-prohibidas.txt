# Contraseñas que SICOT no acepta, una por línea.
#
# QUÉ ES ESTO. Las que más aparecen en las filtraciones públicas, más las que
# un atacante probaría primero CONTRA ESTE SISTEMA en concreto: el nombre de la
# entidad, el del producto, el del Centro y la ciudad.
#
# POR QUÉ HACE FALTA. LoginAttemptService documenta con precisión el ataque de
# «rociado de contraseñas» —probar UNA contraseña común contra MUCHAS cuentas,
# que es lo habitual contra un directorio institucional de correos predecibles—
# y añade el contador por IP justamente para eso. Pero el freno de frecuencia no
# sirve de nada si la contraseña que el atacante va a probar es una que el
# sistema permite: hasta el 20-11-2026 «Password123» era válida aquí. Un límite
# de intentos protege de probar muchas; una lista de bloqueo protege de que la
# primera acierte.
#
# CÓMO SE COMPARA. Ver PoliticaDeContrasena: en minúsculas, sin acentos y
# quitando los dígitos y signos del final, así que «Password123!» se compara
# como «password» y no hace falta listar cada variante. Por eso las entradas van
# en minúsculas y sin números de relleno.
#
# QUÉ NO ES. No es la lista completa de nada: las filtraciones reales tienen
# cientos de millones de entradas. Es el primer puñado, el que cubre la mayor
# parte de los intentos reales con un archivo que se puede leer y auditar. Si
# algún día hace falta más, el paso siguiente es consultar la API de
# «Have I Been Pwned» por prefijo de hash (k-anonimato), que no exige descargar
# nada; se dejó fuera porque añade una dependencia de red a un camino —crear una
# cuenta— que tiene que funcionar en un servidor sin salida a internet.
#
# Las líneas que empiezan por # y las vacías se ignoran.
